# Authorization, privacy and threat model
Deny by default. Customer only own cart/order/vehicle/ticket/reward; public read published active merchants, branches and menu. Merchant owner all own tenant branches, staff, finance; manager assigned branches, catalog operations only where delegated; barista assigned branch queue/transition/arrival only; analyst read permitted aggregates. Admin roles: ops reviews merchants and cancellation; support tickets and masked customer/order data; finance maker requests refund/payout, checker approves different actor; marketing manages campaigns; analyst aggregate reports; security audit/sessions; super admin manages roles, no bypass of financial dual-control. Staff access resolved from active membership on every request; cross-tenant IDs return 404. Scope queries before aggregation, export, object signing and WebSocket subscription. Never accept role or tenant from request body as authority.

## Controls
Verify JWT issuer/audience/signature/expiry; privileged MFA and step-up for role/bank changes, short sessions and revocation. Rate limit login, OTP, claims, pickup code, checkout, uploads and exports by actor/IP; avoid account enumeration. Validate DTOs, parameterized Prisma queries, escape user content, CSP/CSRF protection for cookie sessions, CORS allowlist. Use TLS, managed encryption at rest, secret manager, least-privilege DB roles, separate environments. Signed payment webhook raw-body verification, replay window per provider, unique event ID, reconciliation; don't log raw payload/credentials. Signed upload URLs bound to tenant and size/type; quarantine, malware scan, private bucket, short-lived downloads. Mask plate and PII outside operational need; never include in push payload or analytics. Store pickup code salted hash, rate limit attempts; claim token high entropy and hashed. Audit privileged read/export, policy changes, refunds, payout and role changes with reason and request ID. Append-only journal/audit permissions; alerts on tampering and privilege escalation.

## Threat scenarios and tests
Cross-tenant branch ID manipulation → scoped lookup; duplicate capture/refund → idempotency and locks; forged webhook → reject signature; stale state → version conflict; leaked gift/QR token → revoke and limit claim; malicious file → quarantine; compromised barista → least privilege and revoke; stolen admin session → MFA, step-up and alert; PII in logs → redaction and log scanning; queue replay → durable dedupe. Review dependencies, secret scan, SAST and external penetration test before launch. Privacy notice, consent, access/deletion/retention policies and UAE legal review are launch gates. Do not assert regulatory compliance solely from this design.
